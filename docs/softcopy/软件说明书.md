## 1 引言

### 1.1 编写目的

本文档为「CodeLearning（码上）多语言编程学习软件」的设计说明书，用于计算机软件著作权登记，同时作为后续维护与二次开发的技术基线文档。内容覆盖软件的总体架构、模块划分、数据结构、关键算法、安全机制与测试结论。

### 1.2 背景

现有移动端编程学习产品普遍存在两类问题：一是把代码发送到云端执行，学习过程依赖网络且存在隐私风险；二是用"模拟执行"或"预置答案比对"代替真实解释器，学员无法获得真实的报错与调试体验。

本软件面向希望利用碎片时间系统学习编程的移动端用户，在设备端嵌入真实语言运行时，提供"课程讲解 — 即时运行 — 断言判题 — 错题复习 — 成就激励"的完整闭环，全过程离线完成，学习数据不出设备。

### 1.3 术语

| 术语 | 说明 |
| --- | --- |
| 语言运行时 | 真正执行用户代码的解释器/虚拟机实例，如 CPython |
| 语言包 | 一门语言对应的运行时 + 课程内容的组合（当前内置 Python / JavaScript / Lua / SQL 四个运行时，课程包按需下载） |
| 判题 | 用预置断言脚本检验学员提交代码是否满足题目要求 |
| REPL | 读取—求值—输出循环，即交互式命令行 |
| 守护线程看门狗 | 基于 `sys.settrace` 的执行超时中断机制 |
| 目录自签名 | 内容分发目录对自己"剥离签名字段后"的原文计算 SHA-256 |

### 2.2 主要特点

1. **设备端真实执行**：通过 Chaquopy 内嵌 CPython 3.13，学员代码在手机上由真实解释器执行，报错信息、异常栈与 PC 端一致。
2. **全程离线**：课程、运行时、判题、进度存储全部在本地，无需注册登录，无数据上传。
3. **多语言可扩展架构**：运行时被抽象为统一契约，新增语言只需提供"说同一种 JSON"的后端并注册，界面与判题逻辑零改动。
4. **执行安全边界**：超时中断、输出截断、变量快照体积限制三重护栏，防止死循环与内存膨胀拖垮应用。
5. **内容完整性校验**：分发目录采用自签名机制，包体逐文件哈希比对，路径规范化防目录穿越。

## 5 详细设计

### 5.1 运行时层：多语言抽象

#### 5.1.1 契约定义

`LanguageRuntime` 接口规定了所有语言后端必须提供的能力：

```kotlin
interface LanguageRuntime {
    val id: String              // 语言标识，如 "python" / "javascript"
    val displayName: String     // 展示名
    val fileExtension: String   // 源码扩展名
    val grammarScope: String    // 语法高亮 scope，如 "source.python"
    val version: String         // 运行时版本
    fun isAvailable(): Boolean
    fun ensureStarted(context: Context)
    fun runCode(code: String, stdinLines: List<String>, timeoutSec: Double): RunResult
    fun checkExercise(code: String, tests: List<String>, stdinLines: List<String>): RunResult
    fun warmup(): Boolean
    fun replStart()
    fun replPush(line: String): Pair<Boolean, String>
}
```

统一返回结构 `RunResult` 覆盖执行态（ok）、标准输出、标准错误、错误类型/信息/栈、耗时、变量快照列表、判题通过与否。

#### 5.1.2 注册表

`LanguageRegistry` 承担三项职责：

1. **注册**：应用启动时在 `Application.onCreate` 中集中注册所有可用运行时
2. **当前语言持久化**：写入 SharedPreferences；若首选项残留了已不可用的语言，自动回落到默认语言
3. **安全获取**：`get(id)` 永不返回 `null`——未知 id 先回落默认语言，仍无则回落到 `UnsupportedRuntime`，后者以可读错误回显"该语言未内置"，而非抛异常崩溃。

设计收益：表现层不再出现对具体运行时的引用（已有回归测试强制约束），新增语言时界面代码零改动。

#### 5.1.3 Python 实现

`PyBridge` 以单例对象实现 `LanguageRuntime`，通过 Chaquopy 调用 Python 侧的 `runner` 与 `repl` 模块：

| Kotlin 方法 | Python 入口 | 说明 |
| --- | --- | --- |
| `runCode` | `runner.run_code_json` | 执行代码并返回输出与变量快照 |
| `checkExercise` | `runner.check_exercise_json` | 执行代码后逐个跑判题脚本 |
| `version` | `runner.info_json` | 取解释器版本信息 |
| `replStart` / `replPush` | `repl.start` / `repl.push` | REPL 会话重置与推入 |

所有调用以 JSON 字符串为载荷，避免跨语言类型转换错误。

### 5.2 判题引擎（runner.py）

#### 5.2.1 执行流程

```
输入 JSON → 解析（code/stdin/tests/timeout）
   ↓
_run_protected：重定向 stdout/stderr、接管 input()、安装看门狗
   ↓
exec 用户代码（独立命名空间）
   ↓
[判题模式] namespace.copy() 逐条执行测试脚本
   ↓
变量快照（过滤内置变量、按体积与长度裁剪）
   ↓
输出 JSON（ok/stdout/stderr/error/duration_ms/variables/passed）
```

#### 5.2.2 安全护栏

| 机制 | 参数 | 作用 |
| --- | --- | --- |
| 看门狗 | 默认 8 秒，判题单条 2 秒 | 基于 `sys.settrace` 的守护线程，超时抛出中断异常 |
| 输出上限 | 1 MiB | 超出后保留尾部并标注「输出过长已截断」，防止日志刷屏拖垮 UI |
| 变量数上限 | 40 个 | 快照按最近使用排序后截断，避免插入序截断导致"刚赋值的变量看不到" |
| 单值长度上限 | 200 字符 | 超长 `repr` 截断并追加省略号 |
| 单值体积上限 | 1,000,000 字节 | `sys.getsizeof` 超限则跳过该变量 |
| 异常兜底 | 全链路 | `repr` 抛异常、递归结构、超大对象均安全降级 |

**已知边界**：`sys.settrace` 看门狗只覆盖纯 Python 字节码；若用户代码卡在原生扩展的阻塞调用中，看门狗无法中断。工程上以 8 秒默认超时 + 训练场限制加以缓解，并在代码注释中显式标注该限制。

#### 5.2.3 判题隔离策略

测试脚本在 `namespace.copy()` 上执行，因此：

- 多个测试脚本之间**共享状态**（可编写有顺序依赖的用例）
- 测试脚本**不污染**用户命名空间（用户定义的函数与变量在测试结束后保持原值）

该行为由回归测试 `test_tests_share_state_but_do_not_pollute_user_ns` 锁定。

### 5.3 REPL（repl.py）

维护一个持续的会话命名空间，逐行接收输入：

- 单行语句立即执行并回显
- 多行块（以冒号结尾）进入续行状态，向调用方返回 `more=true`，空行结束
- 会话可通过 `replStart` 重置

### 5.4 课程与内容层

#### 5.4.1 课程数据结构

课程以 JSON 资产内置于 APK，字段如下（节选）：

```json
{
  "id": "l05",
  "order": 5,
  "chapter": 1,
  "chapterName": "基础语法",
  "title": "输入与输出",
  "subtitle": "让程序与你对话",
  "xp": 50,
  "lang": "python",
  "blocks": [ { "type": "code", "code": "...", "runnable": true, "stdin": ["3"] } ],
  "exercise": {
    "title": "求和", "brief": "...", "starterCode": "...",
    "hint": "...", "tests": ["assert add(1,2) == 3"], "stdin": [], "xp": 80
  }
}
```

关键点：

- `lang` 缺省为 `python`，旧课程 JSON 无需任何改动即可兼容
- 代码块可自带 `lang` 覆盖本讲语言，用于"同讲对比两门语言"的教学片段
- `runnable` 控制代码块是否显示运行按钮；来自内容中心下载的包默认不可运行

#### 5.4.2 内容中心安全机制

| 措施 | 实现 |
| --- | --- |
| 目录自签名 | 校验目标是"剥离顶层 `sha256` 字段后的原文"，使目录可被签名且签名值本身不参与计算 |
| 包体哈希 | 每个包必须提供 `sha256`，下载后逐包比对 |
| 白名单 | 包 id 必须命中白名单，防止任意 id 拼路径 |
| 路径规范化 | 目标文件 `canonicalPath` 必须位于 packs 目录 `canonicalPath` 之下，防目录穿越 |
| 响应体积上限 | HTTP 响应 5 MB 封顶，防内存攻击 |

**历史缺陷与修复**：`tools/update_catalog.py` 原实现用正则替换**全部** `sha256` 字段，导致目录对被篡改的"各包哈希"失去校验能力，且与 Kotlin 侧 `replaceFirst` 语义不一致。已改为只剥离顶层字段，并补 4 项回归测试锁定该语义。

## 6 关键算法

### 6.1 间隔重复（SM-2 变体）

```
输入：答题质量 q ∈ {0..5}
若 q < 3：        间隔重置为 1 天，重复次数归零
否则：            重复次数 +1
                 间隔 = 上次间隔 × 难度因子
难度因子 EF' = EF + (0.1 - (5-q) × (0.08 + (5-q) × 0.02))，下限 1.3
```

### 6.2 执行超时中断

```
看门狗线程：记录 deadline = now + timeout
  → 主线程 sys.settrace(钩子)
  → 钩子每次调用检查 now > deadline，超时则抛出自定义中断异常
  → finally 中 sys.settrace(None) 恢复
```

### 6.3 目录自签名

```
签名目标 = 目录原文中【第一次出现】的 "sha256": "<64位hex>" 替换为 "sha256": ""
签名值   = SHA256(签名目标)
校验     = SHA256(剥离后的目录原文) == 目录中的 sha256 字段
```

剥离只作用于顶层字段，各包的 `packs[].sha256` 保留原值并进入签名覆盖范围——否则目录无法防御"包哈希被篡改"的攻击。

## 8 创新点

1. **移动端设备端真实语言运行时 + 完整判题闭环**：把 PC 端的"写代码—运行—看报错—改"体验完整搬进手机，且不依赖网络。
2. **语言无关的执行契约**：运行时被抽象为统一接口与 JSON 载荷，课程数据自带 `lang` 字段，使"一门课程应用扩展到多门语言"成为配置级工作而非架构改造。
3. **面向初学者的错误转译链**：从原始异常栈 → 白话诊断 → 三步引导 → 最小修复片段，全程本地规则实现，无网络无隐私外泄。
4. **可验证的内容分发**：目录自签名 + 逐包哈希 + 路径规范化三重校验，保证离线分发的内容不可被中间人篡改。

## 9 局限性与后续规划

| 局限 | 说明 | 规划 |
| --- | --- | --- |
| 内置运行时为 Python / JavaScript / Lua / SQL | Java / C++ / Go / Rust 需要编译器或原生工具链，无法随 APK 离线提供 | 这四门语言不提供下载入口；新增可解释语言需按 `LanguageRuntime` 契约实现后端并随版本发布 |
| 看门狗无法中断原生扩展阻塞 | `sys.settrace` 只覆盖 Python 字节码 | 缩短默认超时 + 训练场限制；长期考虑进程级隔离 |
| 网页端与 Android 端课程数量不同步 | 网页端曾只内联前 30 讲 | 已统一内容源（web/data.js 由 gen_data.py 从 assets 生成，38 讲全量） |
| 无云同步 | 数据仅存本地，换机需手动备份 | 可选端对端加密同步（默认关闭） |
